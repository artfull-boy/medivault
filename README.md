# MediVault — Secure Outpatient Clinic Database

A containerized **PostgreSQL 16** database environment for an outpatient medical clinic, featuring Role-Based Access Control (RBAC), Row-Level Security (RLS), column-level encryption (`pgcrypto`), and a tamper-evident SHA-256 hash-chained audit log.

---

## 1. Quick Start

### Prerequisites
- Docker & Docker Compose
- Node.js (for password generation — no npm install needed, uses built-in `crypto`)

### Setup & Launch

```bash
# 1. Generate all passwords and write them to .env.example
node scripts/generate-passwords.js

# 2. Open .env.example and confirm TRUSTED_IP (default: 127.0.0.1 for local dev)
#    Then generate config/pg_hba.conf from the template
bash scripts/setup.sh

# 3. Start the containers
docker compose up -d
```

On first launch PostgreSQL automatically runs all init scripts in `init-scripts/` in alphabetical order to create the schema, roles, policies, users, and sample data.

### Reset the Database

If you edit any init script or want a clean slate, wipe the volume and restart:

```bash
docker compose down -v && docker compose up -d
```

## 2. Access Model

```
Windows browser
      │
      │  http://localhost:5050
      ▼
┌─────────────────────┐
│   pgAdmin 4 (web)   │  container: medivault_pgadmin  172.28.0.3
│   port 5050 only    │
└──────────┬──────────┘
           │  Docker-internal TCP  172.28.0.2:5432
           ▼
┌─────────────────────┐
│   PostgreSQL 16     │  container: medivault_postgres  172.28.0.2
│   port NOT exposed  │
└─────────────────────┘
           ▲
           │  Unix socket only
     docker exec medivault_postgres psql -U postgres
```

| Path | Who | Allowed |
|------|-----|---------|
| Browser → pgAdmin web UI | Anyone with pgAdmin credentials | ✅ |
| pgAdmin → PostgreSQL | App users (`dr_house`, `nurse_joy`, etc.) | ✅ |
| pgAdmin → PostgreSQL | `postgres` superuser | ✗ blocked by pg_hba.conf |
| Windows pgAdmin / DBeaver / psql → PostgreSQL directly | Anyone | ✗ port 5432 not published |
| `docker exec` shell → PostgreSQL | `postgres` superuser | ✅ unix socket only |

## 4. Connecting pgAdmin to the Database

1. Open **http://localhost:5050** and log in with the pgAdmin credentials from `.env.example`.
2. Click **Add New Server**.
3. **General** tab → Name: `MediVault`
4. **Connection** tab:
   - Host: `medivault-db` *(Docker service name — not localhost)*
   - Port: `5432`
   - Database: `medivault`
   - Username: any app user (e.g. `dr_house`) — see `.env.example` for the password
5. Click **Save**.

> The `postgres` superuser is blocked over TCP by pg_hba.conf. Use `docker exec` to reach it (see section 6).

## 6. Superuser Access (postgres)

The `postgres` superuser is **only accessible from inside the container shell**. It has no TCP access, even from pgAdmin.

```bash
# Open an interactive superuser shell (password from .env.example → POSTGRES_PASSWORD)
docker exec -it medivault_postgres psql -U postgres -d medivault -W

# One-off commands
docker exec -it medivault_postgres psql -U postgres -d medivault -c "\du"
docker exec -it medivault_postgres psql -U postgres -d medivault -c "\dt"
```

### Password Rotation (without rebuilding)

```bash
node scripts/generate-passwords.js
docker exec -i medivault_postgres psql -U postgres medivault < config/set-passwords.sql
```

## 7. RBAC Design

### Role Privileges Summary

| Role | Patient | Doctor | Appointment | MedicalRecord | Prescription | Invoice | AuditLog |
|------|---------|--------|-------------|---------------|--------------|---------|----------|
| `role_doctor` | SELECT (id, name, dob, phone) | SELECT+UPDATE self | UPDATE status | Full CRUD | Full CRUD | — | — |
| `role_nurse` | SELECT all | SELECT | SELECT | vital_signs only | SELECT | — | — |
| `role_receptionist` | SELECT+INSERT+UPDATE contact cols | SELECT | SELECT+INSERT+UPDATE | — | — | SELECT | — |
| `role_patient` | SELECT+UPDATE own contact cols | SELECT (name, specialty) | SELECT+INSERT | SELECT | SELECT | SELECT | — |
| `role_billing_service` | SELECT (id, name, address) | — | SELECT (completed only via RLS) | — | — | Full CRUD | — |
| `role_auditor` | — | — | — | — | — | SELECT | SELECT + verify fn |
| `role_admin` | SELECT+UPDATE contact cols | Full CRUD | SELECT | — | — | — | — |

### Key Hardening Decisions

- `role_doctor` — column-level SELECT on Patient excludes `billing_address` and `email`
- `role_receptionist` — DELETE removed from Appointment; cancellation is an UPDATE to `status = 'cancelled'`
- `role_admin` — `CREATEROLE` removed; role creation is a superuser-only operation via `docker exec`
- All roles are `NOLOGIN` group roles; individual login accounts are assigned to them in `06_create_users.sh`

## 8. Security Tests

### Test 1 — Patient Row Isolation (RLS)

Connect in pgAdmin as `pat_alice` and run:

```sql
SELECT patient_id, name, email FROM Patient;
```

Expected: **1 row** (Alice only). Bob's record is hidden by `patient_self_policy`.

### Test 2 — Doctor Patient Scope (RLS)

Connect as `dr_house`:

```sql
SELECT patient_id, name FROM Patient;
```

Expected: **Alice Martin only**. Dr. Wilson's patient (Bob) is invisible.

### Test 3 — Billing Service Column + Row Restriction

Connect as `svc_billing`:

```sql
-- Allowed: limited columns
SELECT patient_id, name, billing_address FROM Patient;

-- Allowed: only completed appointments (RLS)
SELECT * FROM Appointment;

-- Denied: full patient row
SELECT * FROM Patient;
```

Expected: third query fails with `ERROR: permission denied for table patient`.

### Test 4 — Column-Level Encryption (pgcrypto)

Connect as `dr_house`:

```sql
-- Raw ciphertext (BYTEA)
SELECT record_id, diagnosis, vital_signs FROM MedicalRecord;

-- Decrypted (seed data was encrypted with the dev key below)
SELECT record_id,
       pgp_sym_decrypt(diagnosis, 'dev_master_encryption_key_2026') AS diagnosis,
       vital_signs
FROM MedicalRecord;
```

> Seed data in `06_seed_data.sql` uses the hardcoded dev key `dev_master_encryption_key_2026`.
> New records inserted by the application should use the value of `MEDIVAULT_ENC_KEY` from `.env.example`.

### Test 5 — Tamper-Evident Audit Log

Connect as `aud_smith`:

```sql
-- Inspect the hash chain
SELECT log_id, db_user, action, object_name,
       left(prev_hash, 12) AS prev,
       left(curr_hash, 12) AS curr
FROM AuditLog;

-- Verify chain integrity
SELECT * FROM verify_audit_log_integrity();
```

Expected: `is_valid = true | All audit log entries verified intact.`

## 10. Network Architecture

Both containers share an isolated Docker bridge network (`medivault-net`, subnet `172.28.0.0/24`) with fixed IPs:

| Container | IP |
|-----------|----|
| `medivault_postgres` | `172.28.0.2` |
| `medivault_pgadmin` | `172.28.0.3` |

pg_hba.conf rules (see `config/pg_hba.conf.template`):

| Rule | Match | Method |
|------|-------|--------|
| Local Unix socket | all users | scram-sha-256 |
| TCP from any IP | `postgres` user | reject |
| TCP from `172.28.0.3/32` | app users | scram-sha-256 |
| TCP from `TRUSTED_IP/32` | app users | scram-sha-256 |
| TCP from anywhere else | all | reject |
